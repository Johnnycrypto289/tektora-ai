TEKTORA BUILD TIERS

Pick the Build That Fits Your Business Right Now

This page is built to make the tier boundaries obvious. Starter upgrades the front end. Business Update fixes one core workflow with custom software. Full Build connects multiple workflows into a stronger operating layer. Custom covers the projects that are too broad or specialized for a standard tier.

How to use this page

Do not think in software categories. Think in business outcomes. Each tier below shows what level of system you are buying, what it feels like in plain English, what stays out of scope, and what a real example could look like.

Naming rule: keep the tier flow locked to Starter, Business Update, Full Build, and Custom. The retired Growth package name does not sit between Business Update and Full Build because that would blur where one workflow ends and a connected operating layer begins.

Proof path: this repo keeps the decision path in one straight line: Starter, Business Update, Full Build, then Custom. Luxe Home stays pinned to Full Build because lead handling, scheduling, install coordination, and homeowner updates all share one connected operating layer.

If you want a cleaner website and better automations, that is Starter. If one broken process needs its own real system, that is Business Update. If sales, ops, and homeowner updates all need to connect, that is Full Build. If the scope spills past those limits, that is Custom.

Proof of control The tier naming, comparison matrix, and homepage pricing mirror are controlled in-repo on this page, not left to softer tier language elsewhere. The retired Growth package is intentionally removed from this decision path. If outside drafts soften the tier boundary, or try to blur Business Update versus Full Build, this page is the control point.
Site-wide proof case Luxe Home Services stays pinned to Full Build here, on the homepage pricing flow, and on its own example page so the Business Update to Full Build jump stays explicit.
Control chain /products sets the tier boundary, the homepage pricing flow mirrors it, and Luxe Home Services proves the Full Build boundary in a concrete example.
Package flow

The package path stays fixed from first click to build call. There are four stops in this flow, and each one exists because the business problem changes shape.

Control checkpoint: if an outside draft softens this package jump by reviving the retired Growth wording, sort it back through the same rule used everywhere else here: one workflow stays in Business Update, connected handoffs move to Full Build, and broader architecture becomes Custom. This is the single-workflow tier. One system like follow-up, quoting, scheduling, or dispatch still explains most of the pain.

This starts when the pain looks like Luxe Home and lives in the handoff between workflows instead of one isolated process.

Luxe Home Services is the proof case for this step, so the jump from one workflow to connected handoffs stays visible inside the package flow itself.

Best fitThe business already looks like Luxe Home, where several workflows and two AI roles need one connected operating layer.
Not for you ifYou can still solve the problem honestly with one workflow build, or the scope already depends on broader custom architecture.

Use this once the standard tier box stops being honest because the build needs broader architecture, deeper integrations, or special operating rules.

The package flow stays explicit here too rather than reviving a softer middle-tier label.

Best fitYou already know extra departments, deeper integrations, or special operating rules are shaping the build before a standard tier can describe it honestly.
Not for you ifThe project still fits cleanly inside Starter, Business Update, or Full Build once the workflow shape is defined clearly.

Starter products support the front edge

AI Receptionist and Online Booking usually belong in Starter when the front-end response layer is still the main issue.

They only push higher when one of those systems becomes the core workflow that actually needs custom logic and operational ownership.

Best fitYou mainly need faster first contact, cleaner booking, and a stronger front-end buying experience.
Not for you ifThe real pain now sits inside one broken workflow or across several connected workflows behind the front edge.

Lead Follow-Up, Quoting & Proposal, and Scheduling & Dispatch fit Business Update when one of them still explains most of the pain.
